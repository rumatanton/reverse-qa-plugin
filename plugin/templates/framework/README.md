# __TARGET__ test framework

Playwright + TypeScript, generated by reverse-qa (`plugin/templates/framework`) and filled from the recon outputs in
`../output/`. Every functional test is a Playwright spec. k6 is used only for performance (`../perf/`).

## Run

    npm run selftest          # the framework checks itself (unit + fixtures against the app)
    npm run test:smoke        # T0: every page loads for its role
    npm test                  # every tier on Chromium
    npm run test:browsers     # smoke, flows and journeys on Firefox, WebKit and a phone viewport
    npm run test:p1           # risk priority 1 only

From the repo root, `node plugin/skills/run-suites/run.mjs --target __TARGET__` runs the tiers in order, cleans up the
test data after each step and archives the run in `../output/runs/`.

## Watch and debug

- `npx playwright test --ui`: UI mode, with a timeline you can scrub.
- `SLOWMO=500 npx playwright test --headed --workers=1`: watch in a real browser.
- `npx playwright test --debug=cli`: pause and step from the terminal.
- `npx playwright show-report`, then open a failed test's trace. With Claude Code, the `playwright-trace` skill reads
  traces from the command line.

## How tests link to everything else

Tags in the test title:

| Tag | Meaning | Used by |
|---|---|---|
| `@TC-AUTH-001` | the test case it automates (`../output/test-cases/cases.yaml`) | Xray results, RTM, coverage |
| `@page:admin/index.php` `@role:Visitor` | the page and role it exercises | role-matrix coverage |
| `@smoke` `@api` `@flow` `@integration` `@authn` `@authz` `@e2e` `@char` `@db` `@a11y` `@visual` | tier | run-suites, reports |
| `@p1` `@p2` `@p3` | risk priority | CI order (`@p1` right after smoke) |
| `F-012` | a confirmed finding the test documents with `test.fail()` | findings, triage |

## Data and clean-up

Global setup resets the database to the seed (row counts proven), empties the PHP log, records the files already in
the app's writable folders, and logs each role in once. Global teardown records what the run left behind (rows above
the seed, new files, PHP log) in `test-results/<run>-cleanup.json`, then deletes the new files and resets the
database. `RQA_NO_CLEANUP=1` keeps the data for debugging.

## Safety

Every request to a stubbed integration (`target.yaml` `integrations` with `test_policy: stub`) or a `never_test` host is
blocked and recorded by the `gateway` fixture. Tests can answer those requests with `gateway.handle()` (the payment
stub), but never reach the real service. The base URL must be in `safety.allowed_test_hosts`.

## Agents

`.claude/agents/` holds Playwright's planner, generator and healer (`npx playwright init-agents --loop=claude --prompts`).
Run Claude Code in this folder to use them. The healer gets only failures that `triage-failures` labelled `test`.
