# scaffold-framework

## Prompt

    node "${CLAUDE_PLUGIN_ROOT}/skills/scaffold-framework/scaffold.mjs" --target <name>

Options: `--force` (overwrite template files that already exist), `--no-install` (copy only), `--no-agents` (skip the
agents and skills).

- It prints one line per stage: files written / kept, dependencies and browsers installed, agents and k6 skills added,
  and `playwright test --list` OK with the number of unit tests collected. Report the lines.
- Existing files are never overwritten without `--force`, so the generator's specs and a person's edits are safe.
- `.mcp.json` and `.claude/settings.local.json` are written per machine (Playwright writes OS-specific commands);
  they are gitignored. Re-run this skill on a new machine.

Rules for every spec, template or generated:
- No skipped tests. A skipped test reports green and tests nothing; a headed run showed 95 of 121 as blank windows
  opening and closing. Generate a test only when it can run (a page gets one only when some role may open it) and let
  a missing input fail with its reason: the smoke tier fails when a guarded page has no role-matrix.csv row, and a role
  with no logged-in session fails the test that asked for it.
- A role with no fixed account gets one per run: `register:` under `test_accounts` in target.yaml (form path, fields
  with `{run}` and `{password}`). Global setup signs it up after the database reset; clean-up deletes the row.
- Fixtures open a page only when the test asks for one. `rolePage` builds on `context`, not on `page`: depending on
  the built-in `page` leaves a blank window next to the real one in every test.
- Open pages with `openPage()` (pages/base.page.ts). A page that hands off to a blocked host while it loads (the payment
  gateway form) stays on screen because the guard answers that navigation 204, but Playwright never gets its load event.

The pinned versions (Playwright 1.65.0, @axe-core/playwright 4.14.0, @xray-app/playwright-junit-reporter 0.16.0) live
in `templates/framework/package.json`. Grafana Cloud k6 skills are left out (paid service, not part of a local run).

## Tools

Bash (node, npm, npx, k6).

## Data

- Reads: `plugin/templates/framework/`, `target.yaml`.
- Writes: `targets/<name>/framework/` (template files, `node_modules`, `.claude/agents`, `.claude/skills`, `.claude/prompts`,
  `.mcp.json`, `seed.spec.ts`, `specs/`), a ledger line.

## Lessons from real runs - Memory

This is the skill's memory. Each failure found while running it: what broke, why, and the rule since. Add one with the fix, in this form: the name of the fix in bold, the date, the name of the person who ran it and confirmed the fix, what failed, the cause, then the rule after a bold **Rule:**.

- **No skips in templates.** 2026-11-10, Anton: a headed run showed 95 of 121 tests as blank windows opening and closing. Causes: skips decided inside the test body (after the fixtures opened a page) and `rolePage` depending on the built-in `page`. **Rule:** no skipped tests (see the rules above); a unit test fails on any `test.skip` in the templates or a `page` dependency in `rolePage`.
- **Answer 204, use openPage.** 2026-11-10, Anton: the payment hand-off page failed accessibility only in slow motion: axe scanned Chrome's error page. Cause: the page auto-submits to the payment gateway; the guard aborted it, Chrome replaced the page, and the scan raced the swap. A 204 answer alone left `page.goto` waiting for a load event that never comes. **Rule:** the guard answers blocked navigations 204 and pages open with `openPage()` (waits on `document.readyState`).
- **Hover, then click.** 2026-11-10, Anton: the customer journey timed out on "View Books", "View Book" and "Remove": other elements covered them. Cause: the buttons sit on cards that flip or slide only on hover. **Rule:** do what a user does, hover the card and then click inside it (`card.hover()`, `card.getByRole(...)`); never `force: true`, which clicks things a user cannot.
- **Allow one fatal line.** 2026-11-10, Anton: a journey failed on PHP fatals from known "redirect without exit" defects that the user never sees (one after add to cart, one after logout). A blanket allow would have hidden new fatals. **Rule:** `allow-php-fatal` names the one `file:line` it allows, on the step that triggers it; every other fatal still fails the test.
- **Role pages reach the stub.** 2026-11-10, Anton: the payment integration test saw the gateway request blocked but its stub never ran. Cause: `rolePage` guarded each role's browser context with a fixed "no handler", so `gateway.handle()` worked only on the default page. **Rule:** role contexts use the test's handler (`gateway.handler`); a self-test proves a role page reaches the stub.
- **Mask personal data.** 2026-11-10, Anton: the first visual reference run captured admin pages listing the seeded customers, real people's names and emails, into screenshots meant to be committed (journey videos and traces had them too). **Rule:** target.yaml `safety.mask_personal_data` masks them in the test database after every reset (`support/seed.ts`, with a check that fails the run if any are left); every reset in the framework goes through `resetToSeed()`. Masking covers photos too: the next recording showed customer profile pictures, some of private people, so the mask also resets each seeded customer's image to the app's default.
- **Open pages with page_params.** 2026-11-10, Anton: page tests opened detail pages bare and four failed with PHP fatals or a 404, a state users only reach by mistake. **Rule:** target.yaml `page_params` gives the query a user arrives with; every tier opens `pageUrl(page)`, and the API tier tests the bare request separately (test.fail with the finding named in `without`).
- **Test hand-off through its flow.** 2026-11-10, Anton: a GET of the payment hand-off page without the payment form logs PHP notices, so a page test on it checks a state no user sees. **Rule:** a POST-only hand-off page is tested through its real flow (the customer journey posts the payment form, the hand-off is blocked, and the order id and amount are compared with the database).
- **openStill for screenshots.** 2026-11-10, Anton: four pages never got a reference screenshot, because two captures in a row never matched. Three causes, none of them app defects: a looping GIF background (75 frames at about 65 ms) on both change-password pages, typed text driven by `setInterval` on the search page, and pages about 8,000 px tall where one full-page capture takes 2-3 s against a 5 s limit. `animations: 'disabled'` stops CSS only. **Rule:** visual tests open pages with `openStill()` (page clock paused before load, run 2 s, then each animated image swapped for its first frame); screenshot timeout 30 s, test timeout 90 s. The first version also broke on two things worth knowing: the app serves PNG files named .jpg as image/jpeg, so the format is read from the bytes, and the home page loads an image from another site that the page cannot read back, so such images are left alone and listed in an `image-not-readable` annotation. A self-test covers all of it.
- **Own login per test.** 2026-11-10, Anton: the first authz run with the role matrix failed 46 of 99 cells and 21 of 33 screenshots, many of them for no app reason. Cause: every test reused the one session global setup logged in, and the matrix opens logout.php as Customer and as Admin, which ended that session for every later test of that role (payment.php and profile.php as Customer, then all the admin screenshots, landed on the login page). **Rule:** `roleRequest` and `rolePage` log in on their own session with `logIn()` (support/target.ts, the target.yaml login form); global setup still logs in once to prove the credentials. A self-test checks that two logins are two sessions.
- **Read log behind redirects.** 2026-11-10, Anton: 14 role-matrix cells (customer pages opened as Visitor or Admin) redirected to login correctly, but the page kept running behind the redirect and died with a PHP fatal. The log watcher failed them, so they never reached the assertion naming F-009 and could not confirm it. **Rule:** the authz test reads the PHP log around every redirect cell and passes the fatals to `evaluateCell` (`serverFatals`); a fatal behind a redirect is `redirect-then-fatal`, execution after redirect, the same as page content in the redirect body.
- **Reset keeps per-run accounts.** 2026-11-10, Anton: in the first full run after the per-test login change, 28 tests failed with "login as Customer did not redirect". Cause: the API tier puts the seed back after its POST tests, and the reset deleted the customer that global setup had signed up; the old shared session had hidden that. **Rule:** `resetToSeed()` (support/seed.ts) signs the per-run accounts up again with the same credentials, so any reset in a run keeps them; a self-test resets and logs in.
- **Serial only when needed.** 2026-11-10, Anton: one failing POST test made Playwright skip the 8 after it, because the group was `describe.serial`. **Rule:** serial only where a test needs an earlier test's result (the payment hand-off); independent tests are never serial. The empty form is posted to the URL a user is on (`pageUrl`, target.yaml page_params), not the bare page: the bare request is the separate "without its parameters" test.
- **Logged fatal counts as error.** 2026-11-10, Anton: the known-defect test for an admin page requested without its id passed although the page crashed: the fatal came after "200 OK" had been sent, and the test only looked at the status. **Rule:** a server error is a 5xx status or a PHP fatal logged during the request (`withServerFatals` in support/target.ts); the bare-request and authz tests use it.
- **Ask capabilities first.** 2026-11-10, Anton: the framework assumed every target is a web app started by the plugin with a database and a PHP log. **Rule:** it asks `capabilities()` (plugin lib/platform.mjs) what the target has. An API target (`app.kind: api`) gets no browser tiers and no browsers; a target with no database gets no reset, snapshots or `db` fixture (a test that asks for one fails with the reason); the log watcher reads `runtime.error_log` with the stack's patterns and is off when no log is configured; clean-up says what it could not clean (`not_cleaned`), never "cleaned up 0 rows".
- **Guard automatic for web only.** 2026-11-10, Anton: the outbound guard fixture asked for a browser context in every test, so an API target with no browsers installed could not run one. **Rule:** the guard is automatic for web apps only; a fixture that needs a browser is never automatic for an API target.
- **Long tests set own timeout.** 2026-11-10, Anton: seven tests timed out at 30 s only while other work was using the machine (two journeys, the accessibility scan of an 8,000 px page, a WebKit page load); the same run repeated clean. **Rule:** a test that walks many steps or scans a long page sets its own time budget; 30 s is for single-page checks.
- **openPage ends on 204 too.** 2026-11-10, Anton: the payment hand-off page timed out on WebKit only, on a quiet machine too. Cause: after the payment hand-off is blocked (answered 204), Chromium and Firefox finish loading the page they stayed on, but WebKit leaves it in "loading" for good, and `openPage()` waited for "complete". A probe on both engines showed it. **Rule:** `openPage()` ends on whichever comes first, the document complete or a navigation answered 204; the check now passes on all three engines.
- **Listing gets its own report.** 2026-11-10, Anton: the dashboard export showed 408 skipped tests. Cause: `playwright test --list` (used to check that the files load) writes the JSON report too, and overwrote the last full run's `report.json` with a listing in which nothing ran. **Rule:** the config names the report `list` when `--list` is on the command line, so listing can never replace a run's report; the real run was restored from `output/runs/`.
- **Electron driver for desktop apps.** 2026-11-11, Anton: a desktop app could be analysed but not tested: its only driver was the planned Appium one. Cause: every driver beyond web and API was assumed to need a device or an emulator. **Rule:** a desktop app built with Electron is driven by Playwright through its own windows (`support/desktop.ts`, target.yaml `app.driver: electron`). Each test starts its own copy of the app with its own data folder and logs in through the app's login screen; `rolePage` returns the app's window, so the smoke and accessibility specs run unchanged. The mini-desktop fixture runs the whole chain (`tests/e2e/desktop-electron.test.mjs`). Mobile, and desktop apps not built with Electron, still wait for Appium.
- **Window errors fail the test.** 2026-11-11, Anton: a desktop app has no server log, so a screen whose script threw an error would still have passed its smoke test. **Rule:** an error nothing caught in one of the app's windows fails the test, the way a server error fails a web test; a documented defect allows only its own with `{ type: 'allow-page-error', description: '<text in the message> <finding>' }`. Four probes proved it: a wrong expectation, an uncaught error and a missing screen each failed with a screenshot and a trace kept, and the allowed error passed.
- **Axe stays in the window.** 2026-11-11, Anton: the accessibility tier failed on all 6 screens of the desktop fixture with "Target.createTarget: Not supported". Cause: axe finishes a scan in a blank tab it opens itself, and an Electron app's windows are opened by the app, never by a test. **Rule:** for a desktop app the scan runs with `setLegacyMode(true)`, which stays in the window; frames from another origin are left out there.
- **Hand runs are named adhoc.** 2026-11-11, Anton: the framework's self-tests, run by hand after a reboot (`npx playwright test --project=selftest --project=unit`), replaced the full run's `report.json` with a 20-test report; the dashboard export would have shown 20 tests where the run had 245. Cause: a run with no RQA_REPORT was named `report`, the file the full tier writes and every report reads. It is the second time (the `--list` lesson above). **Rule:** a run that names no report is called `adhoc`; only run-suites' full tier writes `report.json`. The full run was put back from `output/runs/`.
