## Lessons from real runs - Memory (reverse-qa)

Failures found while running specs this agent wrote, and the rule since. Each starts with the name of the fix in bold, then the date and the name of the person who confirmed it; the rule follows a bold **Rule:**. Follow them over anything above.

- **Never skip a test.** 2026-11-10, Anton: 95 of 121 generated tests were skipped and a run still read as green. **Rule:** no `test.skip()`. Write a test only when it can run; a missing input (no role-matrix.csv, no account) fails with its reason.
- **Hover, then click.** 2026-11-10, Anton: clicks on "View Books", "View Book" and "Remove" timed out because other elements covered them: the buttons sit on cards that flip or slide on hover. **Rule:** hover the card, then click inside it (`card.hover()`, `card.getByRole(...)`). Never `force: true`.
- **Allow one fatal line.** 2026-11-10, Anton: a journey failed on PHP fatals from known "redirect without exit" defects the user never sees. **Rule:** on the step that triggers one, add `{ type: 'allow-php-fatal', description: '<file>:<line> <why>' }`. It allows only that line; any other fatal still fails.
- **Use openPage, test real flow.** 2026-11-10, Anton: the payment hand-off page auto-submits to the payment gateway and Playwright never saw its load event. **Rule:** open pages with `openPage()` from `pages/base.page.ts`, and test a POST-only hand-off through its real flow (form, blocked hand-off, values checked in the database).
- **Use the fixtures.** 2026-11-10, Anton: the gateway stub never ran on a logged-in page. **Rule:** use the fixtures (`rolePage`, `roleRequest`, `db`, `gateway`); `gateway.handle()` applies to role pages too.
- **Fresh customer per run.** Anton: Never log in as a seeded customer: those rows are real people's data. Roles come from target.yaml `test_accounts`; customers are signed up fresh each run.
- **Finding ID starts the message.** 2026-11-10, Anton: a known-defect test (`test.fail()`) passes on any failure, so a broken precondition would "confirm" the finding. **Rule:** start the deciding assertion's message with the finding ID, `expect(x, 'F-009: the comment is still there')`; preconditions get messages without it.
- **Screenshots after openStill.** 2026-11-10, Anton: screenshots of pages with GIFs or timer-driven text never matched twice. **Rule:** take screenshots after `openStill()` from `pages/base.page.ts`, never after a plain `goto`.
- **Sessions from fixtures only.** 2026-11-10, Anton: a test that opened logout.php ended the shared login for every later test. **Rule:** get logged-in pages and requests only from `rolePage` / `roleRequest` (each logs in on its own session); never load `.auth/*.json` storage state in a spec.
- **Journeys set their own timeout.** 2026-11-10, Anton: journeys timed out at the default 30 s when the machine was busy, though every step passed alone. **Rule:** a spec that walks several pages in one test sets its own budget at the top, `test.describe.configure({ timeout: 120_000 })`; never raise the global timeout.
- **Ask what the app has.** 2026-11-10, Anton: tests now also run against apps with no database, no server log, or no browser (an API). **Rule:** ask `caps`, `isWeb`, `hasDatabase` and `hasServerLog` from `support/target.ts` before writing a test that needs one; write the test only where it applies. For an API, log in with `roleRequest` (a token login) and expect `denied` (401 or 403) for a role the app refuses.
- **Missing input fails, never skips.** 2026-11-10, Anton: a hand-written journey still carried `test.skip(!user || !password, …)`; the template guard only reads the templates. **Rule:** in any spec, a missing input is an assertion that fails with its reason (`expect(Boolean(user && password), 'ADMIN_USER … must be set').toBe(true)`), never a skip.
- **Read the trace first.** 2026-11-10, Anton: two journey failures in the other-browser tier were the app, not the test: at phone width the admin menu items overlap so one cannot be tapped, and in WebKit the category cards do not render. **Rule:** when a click or hover waits forever on one browser, read the trace before changing the test (`npx playwright trace open <trace.zip>`, then `trace action <n>`); "intercepts pointer events" or "element is not visible" on a control a user needs is a finding candidate, never a reason for `force: true`.
- **Read the row after a write.** 2026-11-12, Anton: the mutation check on a real app made 12 UPDATE and DELETE statements change nothing, and no test noticed: the tests of those pages only checked that the page answered, and the page says "Corrected the Details" whenever the statement ran, even when it changed no row. Cause: a page that writes was tested like a page that shows. **Rule:** a test of a form or link that edits or deletes ends by reading the changed row from the database (`db.exec`), every column the form sets; the page's own message is never the proof. The test makes the row and the account it changes and removes them afterwards (for example in `tests/own-accounts.ts`), so no shared account, shared password or seeded row is changed. A callback that must be signed is signed by the app's own library inside its container; a key never goes into a test.
- **No serial groups.** 2026-11-10, Anton: on the PHP 8 copy two payment tests were reported as skipped: they sat in a serial group behind a test that fails there, and reused its order. **Rule:** no serial groups. Each test makes the data it needs through a helper (`pendingOrder()` in the payment spec creates an order the way a customer does), so a failure in one test never leaves another unrun.
